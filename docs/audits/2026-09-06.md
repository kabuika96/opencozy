# Opencozy audit — 2026-09-06

Implemented a mobile interaction and Harness reliability pass, with reversible tab management, inspectable agent communication, native child steering, a smaller frontend, and focused regression coverage. Existing user data and live backend processes were preserved.

## Findings and changes

| Area | Finding | Result |
| --- | --- | --- |
| Tabs | Closing required a menu and deleted history; bulk management was missing. | Direct idle-tab close, optimistic removal with rollback, Undo, searchable tab drawer, close others/all idle, and recently closed recovery. Confirmed stop-and-close waits for cancellation and retains unreachable work. |
| Storage | Tab visibility was conflated with Thread lifetime. | Additive `closed_at` migration; device-scoped close/reopen endpoints; bulk updates commit in one transaction. Runs, Timeline Events, context, and previews are preserved. |
| Mobile geometry | Global scrolling/touch suppression and independently positioned controls conflicted with keyboard behavior. | One native Timeline scroller; visible viewport controls shell geometry; composer contains Send; explicit keyboard dismissal; Rename no longer summons the keyboard. Escape dismisses editing/overlays before interrupting a Run, and IME composition cannot accidentally submit. |
| Reading | Streaming and view switches could move a paused reader; long transcripts rendered everything. | Independent Thread/Agent reading positions, conditional follow, explicit jump, and an initial 100-entry window with earlier-history loading. Stable event projections retain unchanged entry identity. |
| Agent navigation | Agent controls competed with transcript scrolling; messages and their recipients were difficult to inspect. | Persistent header navigation, lineage breadcrumbs, compact agent cards, status/task/activity, and a bounded expandable communication transcript. Main and child drafts are independent. |
| Child steering | No direct UI path to send input to a verified active child turn. | Adapter-owned native `turn/steer` using the observed child turn ID; API validates device ownership and active-run membership. Directed user messages persist in the child Timeline. Finished children remain inspectable. |
| Run lifecycle | Native cancellation could fall through to failure; early startup failures could leave steering waiting; interrupted work could overlap the next Run. | Recognized cancellation terminal state, abortable startup, rejected early steering, cleanup-aware cancel response, and single-terminal-event regression coverage. |
| Transport | Failed input responses could become nonretryable; warm connections, stderr, notifications, and requests lacked sufficient bounds. | Await actual stdin response writes before removing interactions; EPIPE handling; 30-second request timeout; 64 KiB stderr and 10,000 queued-notification limits; at most two idle connections; dead-connection replacement and pool-close race handling. Active-run concurrency remains available. |
| Agent events | Early child notifications could be lost or mixed with unrelated activity on reused connections. | Instance-local run state, bounded early-event replay only after verified lineage, namespaced stable keys, observed child turn tracking, and Main/child status isolation. |
| Rendering | SVG geometry was stripped, streaming HTML detection was brittle, resolved requests could look actionable, and grouped tool details were inaccessible. | Safe SVG geometry and partial-HTML rendering, pending/resolved interaction state, and expandable execution/file/tool details with regression tests. |
| Architecture/load | Five Ionic wrappers loaded a component catalog; the shell combined presentation and lifecycle concerns. | Native semantic shell; extracted Timeline entries, viewport and scroll hooks, tabs, agent navigation, and communications. Preview picker loads on demand. Removed unused styles/imports and ignored local runtime/test artifacts. |
| Dependencies | The initial dependency audit reported seven vulnerabilities, five high. | Updated within declared ranges; final full `npm audit` reports zero. Codex remains pinned at `0.153.4`; Playwright is pinned at `1.59.1` for the available browser engine. |
| Local exposure | The existing frontend environment bound every network interface despite the documented localhost/Tailscale boundary. | Corrected local `LITEHARNESS_FRONTEND_HOST` to `127.0.0.1`; this takes effect when the frontend service reloads its environment. |

## Validation

- Initial suite: 148 tests. Final `npm run check`: 89 backend and 95 frontend tests pass; both workspaces typecheck and build.
- Mobile Chromium browser tests run against a separate frontend on `127.0.0.1:5187` with mocked API/WebSocket traffic. They cover layout, immediate close/Undo, bulk close/reopen, confirmed cancellation, agent navigation and directed messages, draft isolation, reading position under streaming/tab changes, loading earlier history, viewport resizing, keyboard dismissal, and menu placement.
- Protocol shapes were checked with the installed pinned Codex package's `app-server generate-ts`. Fake transport tests exercise startup/cancel races, failed delivery, child enrollment/steering, and connection reuse. No paid model inference or user Thread was used for validation.
- Full `npm audit --audit-level=low`: zero vulnerabilities at audit time.
- Playwright WebKit could not launch on this host: its downloaded macOS 14 engine exits with `Bus error: 10` before a page opens, including an isolated retry. WebKit remains an explicit `test:browser:webkit` command. Real iOS keyboard, safe-area, and Safari behavior are not verified by the Chromium viewport emulation.

## Activation and limits

The backend has not been restarted. `AGENTS.md` requires approval because it owns active clients and in-flight Harness Runs. The additive migration and new routes activate on the next approved backend start; refresh clients afterward. The actual local Opencozy services use ports 8797 (backend) and 5183 (frontend); the default ports belong to another project and were left alone. Restart the Opencozy frontend service as well to load its corrected localhost binding.

Closing retains storage intentionally. Recently closed lists the latest 100 closed Threads; the underlying history is not garbage-collected. Directed messages require a child whose current turn is observed by this backend; completed-agent follow-up stays with Main. A delivered collaboration message means the send completed, not that the recipient read or acted on it.

Architecture decisions are recorded in [ADR 0015](../adr/0015-reversible-tabs-and-mobile-viewport.md) and [ADR 0016](../adr/0016-native-mobile-shell.md). The localhost/Tailscale trust boundary and backend-only Codex protocol integration remain unchanged.

## Follow-up: HTTP 500 after restart

The approved restart completed at 08:46 PDT, activating the earlier changes. Vite logged `ECONNREFUSED` for Timeline and state reads during backend startup; these become empty HTTP 500 responses. The backend subsequently accepted the next Run in the same preserved Thread, but frontend read failures still had recovery gaps.

Four failing regression cases reproduced the gaps before the fix: a failed Timeline load with healthy heartbeats, failed startup with and without a saved Thread selection, and an accepted message whose follow-up snapshot fails. Startup failures were stored as permanent operation errors; healthy heartbeats prevented failed reads from retrying; and a snapshot failure could incorrectly restore an already-submitted prompt as a draft.

`MobileShell.tsx` now retries startup reads with cancellation on unmount, tracks failed Thread reads independently of heartbeat health, and separates accepted operations from their follow-up snapshot failures. A successful recovery clears the corresponding read error. Genuine operation failures retain their error and draft. Completed initial loads are marked only after their response is applied, so discarded effect requests cannot suppress history loading.

Validation: `npm run check` passes with 92 backend and 103 frontend tests, both typechecks, and both builds. All six mobile Chromium tests pass, including isolated real backend process restarts with empty HTTP 500 responses for both an open tab and a page reloaded during the outage. Both preserve history, the draft, and Harness context, then submit the next Run in the same Thread. The frontend fix activates through Vite; this follow-up does not require another backend restart.
