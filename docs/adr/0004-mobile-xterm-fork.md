# Mobile Xterm Fork

OpenCozy may own a maintained xterm-derived package for the Mobile Terminal Surface instead of layering phone interaction on top of stock xterm from app code or rebuilding terminal emulation from scratch. The fork is mobile-only: desktop terminal views should continue using stock xterm unless they need the same phone-first interaction hooks. The fork should live inside this repository as its own workspace package, preserve xterm's emulator core, and expose a narrow mobile-facing interface for touch hit testing, selection, composition/input, cursor movement, viewport state, and renderer feedback. App code should use that package boundary instead of private `_core` access. The package should start with the simplest shape that preserves the initial feature set: wrapping/importing stock `@xterm/xterm` is acceptable only while it does not compromise native-feeling input, caret movement, selection/copy, or settings. Once a required hook is unavailable through public APIs, the spike should vendor xterm source into the workspace package rather than cutting the feature set. Terminal-rendered state is the source of truth: Codex prompt text, completions, redraws, cursor position, alternate-screen behavior, and output remain owned by the PTY/xterm path. iOS-native input should be used as an input method and gesture model, not as the visible prompt source of truth. Paste should not be a special OpenCozy action: it should flow through the same input bridge as ordinary iOS text input while preserving terminal-correct paste behavior. The input bridge should enable iOS autocorrect and autocapitalization by default, with separate per-device app settings to disable each. The first spike should include the mobile terminal package boundary, native-feeling input/caret movement, long active-prompt wrapping, text selection/copy, and minimal app settings UI for those two input toggles. Selection should work across output, prompts, and the active input line rather than being output-only. Starting text selection during streaming should pause auto-scroll just like manual scrolling, so streamed output cannot move the selection target underneath the user. Auto-scroll should remain paused after selection ends or clears until the user explicitly returns to bottom with a floating down-chevron control; tapping or focusing the input zone should not be the recovery mechanism because the input zone may be out of view. The floating return-to-bottom control should appear whenever the viewport is away from bottom, not only while output is streaming. Copied text should be normalized for readability by cleaning up terminal layout artifacts such as soft wraps and cell padding, while keeping selected content otherwise intact. Input and selection should be tested together because those gestures share the same mobile interaction space. The gesture model should follow iOS text editing expectations: long presses, drags, selection handles, copy/paste affordances, keyboard focus, keyboard-driven caret movement, and caret visibility should feel familiar to an iPhone user while still sending terminal-correct input to Codex. Active prompt editing may remain single-line in terminal semantics, but long text should wrap visually and support iOS-like caret movement across wrapped visual lines. Keyboard Return should submit by default. The spike should try to replace the mobile arrow and Enter controls with keyboard-driven caret movement, especially the iOS spacebar trackpad gesture, and keyboard return behavior rather than treating the control cluster as the primary editing model. Taps in the input zone should focus the input bridge; taps elsewhere should remain available for terminal interaction such as selecting Codex picker or menu items, not be required to reposition the text caret. The input zone should not need a special visual hint; the terminal-rendered caret should signal active editing. Non-input taps should use terminal-native interaction where possible, such as xterm/PTY mouse semantics when the running terminal app supports mouse tracking. OpenCozy should avoid Codex-specific screen parsing that translates tap coordinates into synthetic arrow/Enter navigation, because that is more brittle. Arrow and Enter controls should appear whenever native input is not focused, and contextually while focused when terminal-native tap interaction is unavailable or insufficient, without an explanatory status hint. They may remain as a temporary fallback during the spike and should be removed from the normal mobile editing path once the replacement interaction model passes real-iPhone validation. The spike should be accepted only after it works on a real iPhone against a live Codex session using `docs/mobile-terminal-iphone-validation.md`; desktop mobile emulation is useful for iteration but not sufficient proof. This accepts an ongoing upstream sync cost in exchange for native-feeling mobile editing while keeping the terminal behavior Codex expects.
